# S4 已回收租约后的重绑预检

日期：2026-11-05。对应开发文档 S4 的 Herdr 重启重绑。

## 本切片

新增插件只读 action `rebind-check`。它仅在人工使用公开 CLI `host recover-lease` 归档旧租约之后运行，核对：

1. RLL 当前未被领取、绑定已过期，业务代次和回执游标与旧协调器记录一致。
2. 旧租约归档、恢复回执、旧绑定和插件记录指向同一项目、会话、Owner 与租约；恢复回执明确为 `verified-stopped-no-replay`，业务摘要、代次与候选数量仍匹配。
3. 旧协调器 PID 已不可见，没有待处理的暂停/停止请求；初始提示和每一代正式交接都有已接受的投递记录。
4. Herdr 当前 Ralph/Lisa 双席就绪。已经收到提示的席位必须保留原生 Agent 会话摘要；从未收到提示的 Lisa 可以是新会话。

任一不满足返回阻断码或 `needs_reconcile`。通过时返回新席位绑定计划和证据摘要，但**不领取新租约、不改动绑定、不恢复协调器、不重发提示**。PID 不可见、原生会话摘要相同和空阻断列表均不能单独证明没有在途提示；人工检查仍是前置条件。该预检也不是跨 RLL、插件文件与 Herdr Server 的原子快照，后续写入动作必须重新核验。

## 验证与下一步

隔离测试使用真实公开 CLI 与伪 Herdr：模拟 Server 更换 Terminal、旧协调器因身份变化退出、人工归档旧租约，再检查 Ralph 原生会话连续且 Lisa 尚未收到提示的场景。预检通过，RLL 仍为未领取，提示总数保持一次。篡改恢复回执或替换 Ralph 原生会话会被拒绝。测试中的 `verified-stopped-no-replay` 是对伪进程场景的模拟，不代表真实用户已完成检查。

下一切片需要设计并实现受控写入：保存跨租约投递来源、原子地归档旧插件记录、领取新租约与绑定双席，从当前代次开始监听新回执，明确任何部分失败后的冻结和人工核对方式。真实 Herdr 重启后的接续与不重复交接仍未验收。
