# S4 显式重绑并保持暂停

日期：2026-11-05。对应开发文档 S4 的“Herdr 重启重绑、未知结果停在待核对、不重复交接”。

## 操作边界

在真实使用前，操作者必须先用 `recovery-check` 核对旧协调器、两席 Agent 和在途投递，再显式调用公开 CLI `host recover-lease`。待 Herdr 两席就绪，插件 `rebind-check` 核对旧租约归档、恢复回执、历史投递和原生会话。新增 `rebind` Pane 展示旧租约、恢复回执、当前代次与新席位；只有输入精确的 `REBIND <证据 SHA-256>` 才触发写入。此输入是操作者声明，不是 CLI 对外部 Agent 状态的独立证明。

重绑入口再次执行预检并比较证据摘要，然后写入独占 `rebind.pending.json` 意图、领取新租约、重新核对并绑定双席、确认 RLL 原代次不变。旧协调器记录和已接受投递移入 `prior-<旧租约 ID>/`；新记录保留旧租约与恢复回执引用，状态为 `rebound_paused`。`recovery-check` 从归档核对历史投递链。整个过程**不调用 `agent prompt`，不重发初始任务，也不自动交接**。

若写入中途失败，意图标记保留，恢复检查返回 `REBIND_PENDING_REVIEW`，由人工检查新旧租约及归档。对 `rebound_paused` 调用 `stop` 会先核对 RLL 游标，再释放替代租约。即使停止，普通 `start` 也会发现归档中的初始提示并拒绝重复投递。

## 验证和未完成部分

隔离测试使用真实公开 CLI 与伪 Herdr，覆盖：旧 Server Terminal 更换后人工归档租约、原生会话核对、正确证据重绑、错误证据拒绝、重绑后不重发、归档投递可核对、重复重绑拒绝、停止释放，以及领取新租约后席位变化时保留冻结标记。Pane 单元测试覆盖取消、精确确认和结果不明时不重试。Herdr manifest 在隔离 XDG 目录中校验。

此切片只实现**显式重绑和暂停**。`resume` 尚不能让暂停的替代租约接续心跳、监听新回执或发送后续交接；真实 Herdr Server 重启场景也尚未验证这条新写入路径。当前仅支持对首次归档的旧租约做一次显式重绑；`rebound_paused` 再次异常时仍需人工核对，不能自动重复接管。下一步必须实现从保存的游标安全启动协调器，并验证新旧租约的回执归属和一次投递。
