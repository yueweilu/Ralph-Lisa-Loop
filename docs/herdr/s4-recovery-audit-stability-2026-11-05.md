# S4 恢复核对期间的状态变化检测

日期：2026-11-05。对应实施文档的 S4 恢复核对切片。

## 问题与改动

原 `recovery-check` 先读取 RLL 租约证据和插件投递记录，再读取 RLL 快照，最后查询 Herdr 的 Ralph/Lisa 席位。查询席位期间，旧协调器可能继续发送租约心跳，插件记录可能变化，原先的结果却仍可能输出第一次读取的状态。

现在，在两席查询结束后再次读取 CLI `host recovery-check` 和插件记录。CLI 证据哈希覆盖租约、绑定、业务代次和候选等恢复证据；插件摘要覆盖完整协调器记录及初始/交接投递记录。任一证据变化、读取失败或记录不匹配，返回 `needs_reconcile` / `RECOVERY_STATE_CHANGED`，不输出 `review_required` 的旧结果。原有席位身份和投递字段校验继续生效。

## 验证与边界

隔离测试使用真实公开 CLI 与伪 Herdr，在 `agent get` 期间分别改动插件记录和租约心跳序号；两种情况均被拒绝。正常恢复审查、提示结果不明、Server 重启和重复启动测试仍通过。

复核仍由多次只读操作组成，无法形成 CLI、插件文件与 Herdr Server 之间的原子快照，也不能证明最后一次读取之后没有新变化。因此它只是减少过时审查结果的窗口，不提供自动回收租约或重发提示的依据。人工仍需核实旧协调器、两席 Agent 和在途投递，再使用显式的 CLI 恢复命令；真实 Server 重启后的自动重绑与租约接续尚未完成。
