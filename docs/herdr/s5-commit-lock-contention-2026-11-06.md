# S5 提交短锁竞争缓解

日期：2026-11-06。承接[GitHub 安装版双席验收](s5-github-dual-agent-live-2026-11-06.md)。该试验的 Lisa 候选经人工来源确认后，唯一一次 `host commit` 返回 `HOST_BUSY`；回执只读查询为 `unknown`，generation 仍为 1，随后命令锁检查为 `absent`。隔离项目已清理，缺少冲突当刻的占锁者证据，不能确认是协调器心跳或其他命令造成。

代码审查确认 `host commit` 在进入候选复核和任何业务写入前先取得项目级短锁；短锁目录已存在时返回 `HOST_BUSY`。本切片仅在**抢锁之前**增加最多 500 毫秒的有界等待，每 25 毫秒重新尝试。取得锁后仍按原有规则核对请求、候选、人工来源确认、租约和代次。持续占锁仍返回 `HOST_BUSY`；不会在提交写入或结果不明后自动重放。

本地构建通过。聚焦的 Lisa 短锁测试覆盖短暂占锁后只提交一次，以及持续占锁时返回 `HOST_BUSY` 且没有 Lisa 回执；同文件的 Ralph/Lisa 写入崩溃矩阵共 4/4 通过，宿主事务测试 23/23 通过。本切片是针对短暂竞争的可靠性缓解，不是旧现场占锁者的根因定位，也不代表 Lisa→Ralph 真实交接已通过。下一次须在新的隔离 GitHub 安装会话中按人工来源确认门禁复验；若仍返回 `HOST_BUSY`，先保存当刻锁检查、请求回执与 CLI 快照，不盲目重发提交。
