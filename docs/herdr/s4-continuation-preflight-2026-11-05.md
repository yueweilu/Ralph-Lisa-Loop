# S4 暂停重绑后的只读接续预检

日期：2026-11-05。对应开发计划 S4 的“Herdr 重启重绑、未知结果停在待核对、不重复交接”。

## 本切片

新增 Herdr Workspace 动作 `ralph-lisa.loop.continuation-check`。它只接受已经完成显式重绑、状态为 `rebound_paused` 的项目，不启动协调器、不续心跳、不发送 Agent 提示。

预检从公开 CLI `host snapshot` 读取业务游标和绑定，再从持久 `host/lease/record.json` 核对替代租约 ID、Owner、会话、项目和状态。`host snapshot` 按契约不暴露租约 ID，因此不能把快照当成租约记录。随后核对插件 `record.json`、旧租约归档、每一条已接受投递、保存的暂停游标、当前 Workspace/Pane，并检查是否存在待处理控制请求。已收到提示的 Agent 必须保有相同的原生会话指纹；两席必须可交互且处于可接收状态。

预检在观察两席后重读 CLI 快照、租约与插件证据。任何状态变化返回待核对；无阻断时返回 `review_required` 与证据 SHA-256，供后续显式接续动作做比较。顺序读取不是原子快照，预检结果不会自行授权写入。

## 验证和边界

伪 Herdr 重启回归覆盖：有效重绑后预检通过；Ralph 原生会话变化、Terminal 变化返回阻断；待处理 `stop.json` 和游标篡改返回待核对；以上路径均未增加 Agent 提示。本地插件套件 24/24 通过，隔离 XDG 配置中的 `herdr plugin link` 接受了新增动作。此处是本地隔离测试与 manifest 校验，不代表真实 Herdr Server 重启验收。

下一切片实现显式接续写入：重跑预检并比较证据，持久化接续意图，基于原游标启动心跳及回执监听，核对新租约回执归属，并保证同一回执只投递一次。任何写入或提示结果不明都留在人工核对状态。
